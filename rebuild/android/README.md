# Мои финансы — Android rebuild v2 (предварительная версия)

**Это новое тестовое приложение, которое устанавливается отдельно от старой версии на Samsung.**

## Статус и ограничения
- Пакет: `by.moifinansy.rebuild`; версия `0.1.0-preview`.
- Данные хранятся офлайн в Room/SQLite, отдельно от прежнего `com.alina.budget` / иных идентификаторов.
- Работают: создание счетов, ручные доходы/расходы/переводы, редактирование, мягкое удаление, история с фильтрами, аналитика за текущий месяц.
- **Резервные копии новой версии:** экспорт JSON через системный выбор файла, контрольная сумма SHA-256 и восстановление строго в пустую базу; исходные удалённые операции и журнал уведомлений сохраняются в архиве. Это не перенос истории из прежнего приложения. Работа на реальном устройстве требует отдельной проверки.
- **Пока НЕ работают:** чтение банковских push, импорт предыдущей истории, перенос из 1.0.6.4, автоматическая миграция старого приложения.
- Название банка само по себе не связывает уведомления со счётом. Привязку вручную выбирает пользователь при создании операции из очереди.
- Поддерживаемые пакеты на этапе тестирования: `com.mobicon.mbank2.belarusbank`, `by.softclub.belarusbank`, `by.alfabank.app.insnc3`, `by.alfabank.abm`. Список основан на старом коде и ещё должен быть проверен на реальных устройствах.

## Сборка
1. Автоматические сборки отключены по просьбе владельца. Для нового APK потребуется явный ручной запуск `workflow_dispatch` в GitHub Actions — только по согласованию. Ранее собранные APK в Artifacts могут не включать последние изменения.
2. GitHub Actions → **Android rebuild v2 preview** → выбрать последний **успешный** запуск из ветки `rebuild-v2`.
3. Скачать архив artifact `moi-finansy-rebuild-preview`, извлечь `app-debug.apk`.
4. Установить APK на Android (только для тестов), не удаляя старое приложение.

Исходники: открыть папку `rebuild/android` как Android Studio/Gradle-проект; JDK 17, Android SDK 35, Gradle 8.11.1.

### Важно об обновлениях
GitHub Actions `assembleDebug` по умолчанию подписывает APK **временным debug-ключом каждого runner**. Следующий APK может иметь другую подпись и **не обновится поверх предыдущего без удаления приложения**. Удаление тестовой версии удалит её локальные данные! До реализации стабильного ключа подписи и экспорта данных используйте **только выдуманные тестовые операции**.

Для стабильных релизов понадобится отдельный защищённый release-keystore (хранимый как GitHub Actions secret, а не в репозитории), воспроизводимое подписание и проверенные миграции БД.

### Как проверить резервную копию (только тестовое приложение)
1. Откройте вкладку **Счета** → **Сохранить JSON**; выберите документ/папку и дождитесь подтверждения.
2. Файл содержит **незашифрованные финансовые данные**; не отправляйте его посторонним и храните в защищённом месте.
3. **Не удаляйте данные, пока файл не проверен.** Сохраните файл вне приложения и проверьте, что он читается.
4. Восстановление допускается **только в пустую базу новой версии** (не в установленную старую версию). Если в новой базе есть счёт, операция или сохранённое уведомление, импорт откажет без изменения данных.
5. Импорт проверяет формат, контрольную сумму, ссылки между сущностями, дубликаты и ограничения сумм; загрузка в БД выполняется одной транзакцией.
6. SHA-256 обнаруживает случайное изменение файла, но **не шифрует и не доказывает подлинность**: не импортируйте файлы из недоверенных источников.

### Автотесты
`gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug` из `rebuild/android`; в CI запускаются также Node-тесты доменной модели. Тесты на эмуляторе не заменяют проверку резервной копии на Samsung.

## Технические принципы
- Сеть запрещена: нет разрешения `INTERNET`, WebView загружает только собственные assets через `WebViewAssetLoader`.
- JavaScript использует узкий мост `FinanceNative` к локальной Room базе. Не вставлять неподконтрольный JavaScript или удалённые веб-страницы.
- Все суммы в базе — целые сотые валюты (Long). Внутренние переводы не участвуют в доходах/расходах.
- Удаление операций мягкое (`deletedAt`); исходные записи в базе остаются.
- Room не использует разрушительную миграцию.
- Парсеры банковских push нельзя включать до реализации постоянного raw-журнала и тестов дедупликации.

## Ручная приёмка текущего этапа
1. Запустить на чистой установке: ничего не падает; счета и история пусты.
2. Добавить BYN-счёт с 100,00 и наличные с 20,00.
3. Расход 4,31 с карты → остаток карты 95,69.
4. Доход 10,00 на карту → 105,69.
5. Перевод 5,00 с карты в наличные → карта 100,69; наличные 25,00.
6. В истории «Все» — ровно три операции; перевод не увеличивает месячный доход или расход.
7. Исправить расход 4,31 на 3,31 → карта 101,69.
8. Удалить доход 10,00 → карта 91,69.
9. Перезапустить приложение → все остатки и история сохраняются.
10. Добавить счёт USD. Попытка перевода с BYN в USD должна показать ошибку и ничего не изменить.
11. Фильтры по типу и счёту возвращают правильное подмножество.
12. Не тестировать update поверх старого APK без подписей и бэкапа.

## Банковские уведомления: проверка приёмки (не на личных финансовых данных)
1. В разделе «Банки» открыть настройки доступа и дать разрешение тестовому приложению Android.
2. Убедиться, что до получения банковского события список пуст и приложение не запрашивает доступ в интернет.
3. С помощью тестового уведомления поддерживаемого банковского пакета проверить запись в очередь. Новые расходы автоматически не создаются.
4. Убедиться, что сообщения из Telegram и коды входа банка в очередь не попадают.
5. Нажать «Внести операцию», вручную выбрать счёт, сумму, направление, проверить дату, сохранить. В очереди запись исчезает, в истории появляется ровно одна операция, остаток изменяется один раз.
6. Попытка повторной обработки исходной записи должна быть отклонена транзакцией базы данных.
7. Нажать «Не операция» для другой записи: она остаётся в резервной копии и не участвует в балансе.
8. Экспортировать JSON и восстановить в пустую тестовую базу. Журнал, статусы и исходные связи должны сохраниться.

**Ограничение доступа:** Android предоставляет разрешение чтения уведомлений целиком, но код приложения фильтрует их до записи в базу. Если вы не готовы предоставить такой доступ, не включайте его: ручные счета и операции остаются работоспособными.

**Почтовые уведомления GitHub:** сборки запускаются только вручную. Системные письма GitHub Actions выключаются индивидуально пользователем в `https://github.com/settings/notifications` → System → Actions → Don't notify. Код проекта не может изменить личные настройки подписки.

**Безопасность резервной копии:** JSON содержит финансовые записи и исходные тексты банковских уведомлений в незашифрованном виде. Не публикуйте его в GitHub, не пересылайте посторонним и храните в защищённом каталоге. SHA-256 подтверждает целостность файла, но не обеспечивает секретность или защиту от подмены злоумышленником.
