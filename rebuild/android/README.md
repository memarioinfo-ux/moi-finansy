# Мои финансы — Android rebuild v2 (предварительная версия)

**Это новое тестовое приложение, которое устанавливается отдельно от старой версии на Samsung.**

## Статус и ограничения
- Пакет: `by.moifinansy.rebuild`; версия `0.1.0-preview`.
- Данные хранятся офлайн в Room/SQLite, отдельно от прежнего `com.alina.budget` / иных идентификаторов.
- Работают: создание счетов, ручные доходы/расходы/переводы, редактирование, мягкое удаление, история с фильтрами, аналитика за текущий месяц.
- **Пока НЕ работают:** чтение банковских push, импорт предыдущей истории, резервное копирование, восстановление, перенос из 1.0.6.4, автоматическая миграция старого приложения.
- Значки/названия банков в предыдущей версии не означают, что в этой тестовой версии подключены банки.

## Сборка
1. GitHub Actions → **Android rebuild v2 preview** → выбрать последний **успешный** запуск из ветки `rebuild-v2`.
2. Скачать архив artifact `moi-finansy-rebuild-preview`, извлечь `app-debug.apk`.
3. Установить APK на Android (только для тестов), не удаляя старое приложение.

Исходники: открыть папку `rebuild/android` как Android Studio/Gradle-проект; JDK 17, Android SDK 35, Gradle 8.11.1.

### Важно об обновлениях
GitHub Actions `assembleDebug` по умолчанию подписывает APK **временным debug-ключом каждого runner**. Следующий APK может иметь другую подпись и **не обновится поверх предыдущего без удаления приложения**. Удаление тестовой версии удалит её локальные данные! До реализации стабильного ключа подписи и экспорта данных используйте **только выдуманные тестовые операции**.

Для стабильных релизов понадобится отдельный защищённый release-keystore (хранимый как GitHub Actions secret, а не в репозитории), воспроизводимое подписание и проверенные миграции БД.

## Технические принципы
- Сеть запрещена: нет разрешения `INTERNET`, WebView загружает только собственные assets через `WebViewAssetLoader`.
- JavaScript использует узкий мост `FinanceNative` к локальной Room базе. Не вставлять неподконтрольный JavaScript или удалённые веб-страницы.
- Все суммы в базе — целые сотые валюты (Long). Внутренние переводы не участвуют в доходах/расходах.
- Удаление операций мягкое (`deletedAt`); исходные записи в базе остаются.
- Room не использует разрушительную миграцию.
- Парсеры банковских push нельзя включать до реализации постоянного raw-журнала и тестов дедупликации.

## Ручная приёмка текущего этапа
1. Запустить на чистой установке: ничего не падает; счета и история пусты.
2. Добавить BYN-счёт с 100,00 и наличные с 20,00.
3. Расход 4,31 с карты → остаток карты 95,69.
4. Доход 10,00 на карту → 105,69.
5. Перевод 5,00 с карты в наличные → карта 100,69; наличные 25,00.
6. В истории «Все» — ровно три операции; перевод не увеличивает месячный доход или расход.
7. Исправить расход 4,31 на 3,31 → карта 101,69.
8. Удалить доход 10,00 → карта 91,69.
9. Перезапустить приложение → все остатки и история сохраняются.
10. Добавить счёт USD. Попытка перевода с BYN в USD должна показать ошибку и ничего не изменить.
11. Фильтры по типу и счёту возвращают правильное подмножество.
12. Не тестировать update поверх старого APK без подписей и бэкапа.
