# Этап 3 — банковские push-уведомления (план реализации)

Текущий APK — ручной учёт. Этот документ фиксирует контракт для следующего этапа без имитации работающей банковской интеграции.

## Безопасность и разрешения
- Не требовать разрешения на чтение уведомлений при первом запуске: пользователь сам включает автоматический учёт.
- Использовать `NotificationListenerService` с системным экраном выдачи разрешения.
- Фильтровать события **только по проверенному списку package name банков**. Название уведомления само по себе не служит подтверждением банка.
- Не отправлять уведомления, SMS, токены или данные карт в сеть. Не сохранять полный номер карты, пароли и другие секреты.
- Убедиться, что банковские уведомления на конкретной модели Samsung доступны listener-у, а не скрыты банком/Android.

## Архитектура
1. `onNotificationPosted` получает уведомление и извлекает только нужные метаданные: пакет, заголовок, текст, время, при необходимости маску карты.
2. Записывает событие в `notification_events` как `pending` **до** попытки парсинга.
3. Присваивает устойчивый fingerprint, учитывающий банк/текст/сумму/время/идентификатор операции, если он есть. Повторная доставка одного события не приводит к дублю; две реальные одинаковые покупки в разное время не должны схлопываться.
4. Парсер банка возвращает `TransactionDraft`: сумма в целых сотых, валюта, тип, дата, маска карты, торговая точка, уверенность, исходный fingerprint.
5. Если счёт однозначно определён и распознана операция, в одной DB-транзакции вставить запись и пометить событие `processed`. Если не хватает счёта/суммы — `needs_review` без изменения баланса.
6. Входящие события не удалять при ошибке разбора. Сохранять диагностическую причину, чтобы пользователь мог вручную разобрать событие.
7. Повторная обработка всех `pending` и `needs_review` выполняется идемпотентно.

## Парсеры и тестовые источники
Начать с текущих банков пользователя: Mbank, Беларусбанк, Альфа-Банк/InSync, Приорбанк. Внести конкретные Android package names только после подтверждения по реальному устройству/официальным приложениям. Поддерживать разные формы уведомлений, валюту и тип операции. Сообщение о балансе, входе, переводе собственных денег и списании нельзя считать автоматически обычным расходом.

- Тестовые push — только обезличенные образцы; номера карт скрывать.
- Для каждого банка: расход, доход/возврат, перевод, недостаток данных, повтор, одинаковые суммы в разное время.
- Проверять валюту и счёт до влияния на баланс.
- Не создавать покупки из push с неполной суммой или неизвестным знаком.

## UI/UX
- Экран «Банковские уведомления»: статус разрешения, доступные банки, количество разобранных и ожидающих.
- Очередь «Нужно проверить» с оригинальным банковским текстом и предлагаемой суммой; подтверждение создаёт только одну транзакцию.
- Возможность назначить карту/счёт и магазин, указать категорию и запомнить правило.
- «Все операции» включает ручные и банковские в едином журнале с меткой источника.

## Критерии готовности
- После перезагрузки телефона и закрытия UI listener не теряет уже полученные записи.
- На 1000 уведомлениях нет дублей и потерь по сравнению с количеством исходных raw-событий.
- Сбои парсера не удаляют исходные события и не меняют остатки.
- Двукратная обработка очереди не создаёт повторных транзакций.
- Импорт банковских выписок не должен задвоить подтверждённые push-операции.
- Нет доступа к уведомлениям других приложений вне явно выбранных банков в прикладной обработке.
- Отдельная интеграционная сборка и тесты на Samsung до обещания фонового автоматического учёта.
